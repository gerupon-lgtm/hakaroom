## フェーズ0: 技術検証（最優先）

要確認No.3（WebXR Hit Test/AnchorsのPixel 6a上での挙動）に対応する。ここが通らないと以降のAR実装方式が決まらない。

### T-001: プロジェクト雛形とCI/デプロイ
- 完了条件: `npm run dev` でローカル起動、`npm test` が通る、GitHub ActionsでGitHub Pagesへ自動デプロイされる
- 検証方法: 空のVite+TypeScriptプロジェクトをHTTPS（実機確認用トンネル含む）で開けること。デプロイ後のURLにPixel 6aのChromeでアクセスできること

### T-002: 対応環境チェック（F-001）
- 完了条件: WebXR/Hit Test非対応環境で理由付きのメッセージが表示され、対応環境では次画面へ進める
- 検証方法:
  - 正常系: Pixel 6a + Android Chromeで「対応」と判定される
  - 異常系: PCブラウザ（WebXR非対応）で理由付きの非対応メッセージが出る
  - 異常系: HTTPSでない場合の挙動を確認する（GitHub Pagesは常時HTTPSのため主にローカル開発時の確認）

### T-003: 技術検証A（素のWebXR Device API）
- 依存: T-001, T-002
- 完了条件: 2点間の距離をWebXR Device APIのHit Testのみで計測できるプロトタイプが動く
- 検証方法: 実機（Pixel 6a）で既知距離（1m/2m/3m）を複数回計測し、誤差・ばらつき・失敗条件を記録する（要件定義書17章の検証記録フォーマットに準ずる）

### T-004: 技術検証B（Three.js）
- 依存: T-001, T-002
- 完了条件: T-003と同じ計測をThree.js経由のWebXR統合で実装したプロトタイプが動く
- 検証方法: T-003と同一条件（同じ場所・同じ既知距離）で計測し、誤差・実装コスト・保守性を比較できる記録を残す

### T-005: 採用方式の決定
- 依存: T-003, T-004
- 完了条件: A/B比較の結果を `基本設計サマリ.md`「主要な設計判断」に追記し、`docs/implementation-guide.md` の前提節と `ArBackend` 実装方針を確定する
- 検証方法: 比較結果（精度・ばらつき・実装コスト）が記録され、以降のタスクで参照する実装（`src/ar/webxr-native/` または `src/ar/threejs/`）が1つに定まっている

## フェーズ1: MVP（部屋計測コア）

### T-006: ArBackend共通インターフェース実装
- 依存: T-005
- 完了条件: `ArBackend` インターフェースを採用方式で実装し、画面側から差し替え可能な状態になっている
- 検証方法: インターフェースのモック実装でユニットテストが通り、実機で `start()`→`hitTest()` の一連が動く

### T-007: 4点記録・1点戻る・任意点削除（F-002, F-003, F-006, F-007）
- 依存: T-006
- 完了条件: 長方形4点を記録し、1点戻る・任意点削除ができる
- 検証方法:
  - 正常系: 4点記録→S-004へ遷移
  - 異常系: 「1点戻る」で直近1点のみ取り消される
  - 異常系: 任意点削除で選択した点だけが除去され、他の点の `order` は変わらない
  - 異常系: 追跡ロスト発生時、記録済み測点が保持されたまま基準取り直しダイアログが出て再開できる（要件定義書7.2）
  - 境界: 測点0件で「ここで終了」を選んだ場合、警告が出てS-004へ進まない

### T-008: 壁長・面積の計算（F-004）
- 依存: T-007
- 完了条件: 記録した測点からraw（生値）の辺長・周長・面積・閉合誤差が計算される
- 検証方法:
  - ユニットテスト: 1辺1mの正方形→面積1.0m²、周長4.0m
  - ユニットテスト: 3-4-5の直角三角形相当の座標→期待される辺長・面積と一致
  - 境界: 4点未満では計算しない（`null` のまま）

### T-009: 簡易平面図（F-005）
- 依存: T-008
- 完了条件: 測点と寸法値からSVGで簡易平面図が表示される
- 検証方法: 正方形・L字形（将来）双方でSVGが破綻なく描画される。辺の数値ラベルが対応する辺に表示される

### T-010: 精度検証記録の保存・一覧表示（F-008）
- 依存: T-008
- 完了条件: セッション完了時に検証記録が自動生成され、S-005で一覧・詳細表示、編集、削除ができる
- 検証方法:
  - 正常系: 完了→一覧に1件追加される
  - 正常系: 詳細画面で実測値・メモを編集でき、`editedAt` が更新される
  - 正常系: 削除すると一覧から消え、復元できない（確定仕様の確認）
  - 境界: 101件目の記録追加で最古の1件が自動削除される（NF-データ保持）

### T-011: 測点の安定性表示（F-017）
- 依存: T-006
- 完了条件: 測点位置のばらつきが閾値を超えた場合に静止・再試行を促す表示が出る
- 検証方法: 実機で意図的に端末を揺らし、警告が表示されることを確認する（閾値は技術検証結果を踏まえて調整、【想定】）

## フェーズ2: 縮尺基準・補助計測

### T-012: 基準モード選択画面（F-012）
- 依存: T-006
- 完了条件: 基準なし／メジャー／登録済み基準物／任意基準物の4モードを選択できる
- 検証方法: 各モード選択でS-003内の対応する入力UIに切り替わる

### T-013: 登録済み基準物（A4）の自動検出+手動修正（F-013, F-014）
- 依存: T-012
- 完了条件: A4用紙を撮影すると輪郭候補が表示され、利用者が端点を修正して確定できる。確定前は補正計算に使われない
- 検証方法:
  - 正常系: 撮影→候補表示→修正→確定→`confirmedCorners` が設定される
  - 異常系: 確定操作前は `estimateScaleFromReferenceObject` がnullを返す（C-03のユニットテスト）
  - 異常系: 対象と非同一平面での撮影時に警告が出て再撮影を促す（ブロック、確定）

### T-014: 任意基準物・メジャーモードの実装（F-011）
- 依存: T-012
- 完了条件: 両端点の指定＋実寸入力で縮尺基準を登録できる
- 検証方法: 正常系（入力→縮尺反映）、異常系（実寸未入力での確定を拒否）

### T-015: 幾何条件による比較・補正（F-015）
- 依存: T-008, T-013
- 完了条件: 床平面・垂直壁・直角の全条件を用いた補正が `corrected` に反映される
- 検証方法: 既知の直角部屋データで補正前後の誤差を比較するユニットテスト。改善しないケースでも例外を投げず `raw` を維持する

### T-016: リアルタイム重複撮影・対応点手動指定（F-009 リアルタイム, F-010）
- 依存: T-006
- 完了条件: AR中に複数画像を撮影し、同一点を手動指定できる
- 検証方法: 対応点2組以上の指定でWebXR測点との比較結果が表示される。対応点1組以下では警告

### T-017: バッチ撮影・対応点結合（F-009 バッチ）
- 依存: T-016
- 完了条件: AR起動なしで読み込んだ複数枚の写真から対応点を指定し、比較・補正に利用できる
- 検証方法: 写真読み込み→2枚選択→対応点指定→保存、を1回の操作で完結できる（中断・再開不要の確認）

### T-018: 簡易2点間距離計測（F-016）
- 依存: T-006, T-012
- 完了条件: 部屋計測とは独立したセッションとして2点間距離を計測し、検証記録に保存される
- 検証方法: 正常系（2点記録→距離表示→保存）、境界（1点のみでは結果に進めない）

### T-019: 寸法の手修正（F-018）
- 依存: T-008
- 完了条件: 辺ごとに手入力値を保存でき、`raw` は変更されない
- 検証方法: 手入力後も生値タブで元の計算値が表示される（C-02の確認）

## 非機能要件タスク

### T-022: データ保持のFIFO自動削除（NF-データ保持）
- 完了条件: `verificationRecords` が100件を超えたら最古の記録から自動削除される
- 検証方法: 101件投入後、件数が100件で最古の1件が消えていることをユニットテストで確認

### T-023: バージョン表示・SIKUMILABブランド表示（NF-バージョン表示）
- 完了条件: 全画面のフッタに `hakaroom-MAJOR.MINOR.PATCH` と `© 2026 SIKUMI LAB` が表示され、`src/version.ts` の値と一致する
- 検証方法: `APP_VERSION` を変更してフッタ表示が追従することを確認する同値検証テスト

### T-024: タイムゾーン処理（NF-タイムゾーン）
- 完了条件: 検証記録の日時がUTC保存・JST表示（フォールバック含む）される
- 検証方法: `TZ=UTC` のCI環境で、UTC保存値からJST表示への変換が正しいことを確認するユニットテスト

### T-025: データ非送信の静的検証（NF-データ非送信、C-01）
- 完了条件: `src/` 配下に `fetch`/`XMLHttpRequest`/`WebSocket` 等の外部通信APIが使われていないことを検査するスクリプトまたはlintルールがある
- 検証方法: 検査スクリプトをCIに組み込み、意図的にネットワーク呼び出しを追加した場合に検知できることを確認する
